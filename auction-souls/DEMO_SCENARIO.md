# Стадия 2 — сценарий демонстрации

**Тема:** техническое проектирование и базовая серверная инфраструктура.

## Что реально реализовано
- сервер Node.js + Colyseus;
- комната `game`, максимум 4 клиента;
- подключение игрока по имени;
- состояние игрока: `name`, `hp`, `maxHp`, `souls`, `alive`, `ready`;
- лобби с переключением готовности;
- журнал событий подключения, отключения и готовности;
- автоматический тест базовой инфраструктуры.

**Пока не реализованы:** ставки, предметы, выбор цели, автоматический старт матча, победитель и полный игровой цикл. Это следующий этап.

## Подготовка
Откройте терминал именно в папке, где находится `package.json`. Если команда `dir` не показывает его, перейдите во вложенную папку проекта.
```bat
node -v
npm -v
npm install
```

## Демонстрация (примерно 2–3 минуты)
1. Покажите структуру: `server.js`, `rooms/GameRoom.js`, `rooms/GameState.js`, `rooms/PlayerState.js`, `public/`, `test/`.
2. Запустите `npm start` и оставьте окно открытым.
3. Откройте `http://localhost:2567` в двух вкладках, введите разные имена.
4. Покажите, что оба клиента видят список игроков, у каждого 3 HP и 10 душ.
5. Нажмите кнопку готовности в одной вкладке и покажите изменение статуса во второй.
6. Закройте одну вкладку и покажите событие отключения.

## Автотест
Во втором терминале в той же папке выполните:
```bat
npm test
```
Тест содержит 8 проверок базовой инфраструктуры. Ожидаемая итоговая строка при успехе: `ИТОГ: проверок 8, ошибок 0`. Если тест завершился ошибкой, не утверждайте, что он пройден; сохраните текст ошибки.

## Возможные вопросы
**Почему Colyseus?** Он предоставляет комнаты и синхронизацию состояния, уменьшая объём сетевого кода, который пришлось бы писать вручную.

**Что делает сервер сейчас?** Создаёт комнату, принимает игроков, хранит их состояние, обрабатывает готовность и синхронизирует изменения.

**Где ставки и предметы?** Они входят в требования к будущей версии, но в текущем коде ещё не реализованы.

**Что получает Женя?** Комнату `game`, поля `GameState`/`PlayerState` и сообщение `ready`. Точный контракт — `CLIENT_SERVER_CONTRACT.md`.
