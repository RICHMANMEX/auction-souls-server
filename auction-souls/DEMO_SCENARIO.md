# Стадия 2 — что показывать (сценарий)

**Тема стадии:** техническое проектирование и базовая инфраструктура.
Что реально есть на этой стадии: сервер на Node.js + Colyseus, комната до 4 игроков,
вход по имени, лобби с готовностью, синхронизация состояния, выход игрока.
Игрового цикла (предметы, ставки) ЕЩЁ НЕТ — это план стадии 3, так честно и говори.

## Подготовка
```bash
npm install   # один раз
```

## Показ (5–7 минут)

1. **Структура проекта** (VS Code): `server.js`, `rooms/GameRoom.js`, `rooms/GameState.js`,
   `rooms/PlayerState.js`, `public/` — временный клиент для отладки, `test/`.
   Слова: «сервер — единственный источник истины; клиент только отображает состояние».

2. **Запуск сервера:**
```bash
npm start
```
   Показать консоль: сообщения о старте и создании комнаты. Открыть http://localhost:2567.

3. **Две вкладки = два игрока.** Войти («Анна», «Борис»), показать: оба видят друг друга
   в таблице, одинаковые HP/души. Нажать «Я готов» в одной вкладке — во второй статус
   меняется без перезагрузки. Слова: «состояние синхронизирует Colyseus Schema — сервер
   рассылает только изменившиеся поля».

4. **Выход игрока:** закрыть одну вкладку — в консоли и журнале видно отключение.

5. **Автотест (по желанию):**
```bash
npm test
```
   Ожидаемый итог: `ИТОГ: проверок 7, ошибок 0`.

## Возможные вопросы
- «Почему Colyseus?» — готовые комнаты, матчмейкинг и синхронизация состояния; меньше
  самописного сетевого кода.
- «Где игровая логика?» — план стадии 3: фазы, ставки, аукцион; контракт сообщений уже
  спроектирован (см. отчёт stage_2.docx, раздел 8).
- «Что видят клиенты?» — только общее состояние; скрытых ставок пока нет, потому что
  ставок пока нет.
